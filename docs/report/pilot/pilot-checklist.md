# Pilot checklist

For running Campus TAB in one or two schools for a term before a wider launch. Each line has an owner: **Us** (Campus TAB), **Chief** (the school's Chief Admin), **Principal**, **Office** (Clerk).

## Four weeks before

| Done | Step | Who |
| --- | --- | --- |
| ☐ | Everything in [Before going live](before-going-live.md) that the pilot needs: hosting, domain, email, SMS (DLT), legal review, penetration test | Us |
| ☐ | Data processing agreement signed | Us + Chief |
| ☐ | Licence issued in the platform console (plan, modules, seats) and the key handed over in person | Us |
| ☐ | Agree what success means: e.g. daily attendance by 9:30 on 95% of days, marks for one test entered online, first fee receipts from the counter, parent sign-ins | Us + Principal |
| ☐ | Name a pilot lead at the school and a support contact at our side (phone and WhatsApp hours) | Chief |

## Two weeks before

| Done | Step | Who |
| --- | --- | --- |
| ☐ | Activate the school with the key; the Chief sets up MFA | Chief |
| ☐ | School profile, logo, grievance contact, academic year, classes and sections, subjects, teacher assignments ([admin training guide](admin-training-guide.md), part 1) | Chief + Office |
| ☐ | Import students and staff from Excel (check report first, then commit) | Office |
| ☐ | Publish the privacy notice (after the legal review) | Chief |
| ☐ | Fees set up: heads, plans, instalments; raise dues; one Fee Collector named | Principal + Office |
| ☐ | Staff accounts: each person sets their own password from their link; Clerk and above set up MFA | Everyone |
| ☐ | Parent logins switched on for the pilot classes; letter to parents with how to sign in and give consent | Office |
| ☐ | Android app built for the pilot server and installed on the teachers' phones (or the web app bookmarked) | Us |

## Training (one week before)

| Done | Session (45 minutes each) | Who attends |
| --- | --- | --- |
| ☐ | Office: admissions, imports, attendance officer duty, fee counter and day-end closing | Clerk, Fee Collector |
| ☐ | Teachers: attendance on the phone, class tests and the markbook, student leave | Class and subject teachers |
| ☐ | Principal: approvals, leave, corrections to locked marks, report cards, year-end, privacy office | Principal, Vice Principal |
| ☐ | Chief: roles, support access, audit log, exports, retention, incidents | Chief |

## During the pilot (weekly)

| Done | Check | Who |
| --- | --- | --- |
| ☐ | Attendance taken every school day (Attendance → daily summary) | Principal |
| ☐ | Leave requests moving within 48 hours | Principal |
| ☐ | Fee day-end closings confirmed every day; reconciliation mismatches looked at | Office + Principal |
| ☐ | Data requests inbox: nothing late | Chief |
| ☐ | Retention report read and confirmed (or left) | Chief |
| ☐ | Support tickets and feedback collected; a 20-minute call with the pilot lead | Us |
| ☐ | Backups and restore drill on schedule; error and uptime monitoring quiet | Us |

## End of the pilot

| Done | Step | Who |
| --- | --- | --- |
| ☐ | Compare with the success measures | Us + Principal |
| ☐ | Report cards for the term generated, checked, published | Principal |
| ☐ | Fix list agreed and dated; go or no-go for more schools | Us |
